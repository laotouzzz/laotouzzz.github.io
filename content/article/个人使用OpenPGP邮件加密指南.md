## 个人使用 OpenPGP 邮件加密指南

OpenPGP 看起来复杂，主要是因为同时涉及“公钥、私钥、指纹、User ID、密钥服务器、签名、加密”等多个概念。

个人使用时，只要先记住一句话：

> **别人用你的公钥给你加密，你用自己的私钥解密。**

---

## 一、OpenPGP 是什么

OpenPGP 是一种公开的加密标准，可以用于：

- 加密邮件
- 加密文件
- 对邮件或文件进行数字签名
- 验证内容有没有被篡改
- 验证内容是否由某一把私钥签名

它并不依赖某一家邮箱服务商。

例如 Gmail、Outlook、Disroot、自建邮箱等，都可以配合支持 OpenPGP 的客户端使用。

常见工具包括：

- Thunderbird
- Kleopatra / GnuPG
- OpenKeychain

---

## 二、一套 OpenPGP 密钥包含什么

### 1. 公钥 Public Key

公钥可以公开，也可以发送给别人。

别人想给你发送加密内容时，需要使用你的公钥。

可以简单理解为：

```text
公钥 = 锁
```

别人拿到你的“锁”，就可以把内容加密，但不能用它解密。

### 2. 私钥 Private Key

私钥必须由自己保存。

可以理解为：

```text
私钥 = 钥匙
```

别人使用你的公钥加密后，只有对应私钥才能解密。

因此：

```text
公钥 → 可以公开
私钥 → 不要发送给别人
```

谁获得了你的私钥，谁就可能拥有你的解密和签名能力。

### 3. 指纹 Fingerprint

Fingerprint 是一把 OpenPGP 密钥的唯一标识。

例如：

```text
28A7 6F4B 12E9 7DB6
BCC4 22FB BC90 D06A
1BAF 6652
```

指纹：

- 不是密码
- 不能用于解密
- 可以公开
- 主要用于确认公钥身份

可以简单理解为：

```text
完整公钥 = 一整张身份证
Fingerprint = 身份证号码
```

---

## 三、OpenPGP 公钥和私钥长什么样

### 公钥

导出的公钥通常类似：

```text
-----BEGIN PGP PUBLIC KEY BLOCK-----

mDMEZxxxxxxxxxxxxxxxxxxxxxxxx
xxxxxxxxxxxxxxxxxxxxxxxxxxxxx

-----END PGP PUBLIC KEY BLOCK-----
```

公钥数据中通常包含：

- 公钥参数
- User ID
- 邮箱地址
- 创建时间
- 有效期
- 子密钥
- 自签名
- 算法信息

### 私钥

私钥通常类似：

```text
-----BEGIN PGP PRIVATE KEY BLOCK-----

xxxxxxxxxxxxxxxxxxxxxxxxxxxxx
xxxxxxxxxxxxxxxxxxxxxxxxxxxxx

-----END PGP PRIVATE KEY BLOCK-----
```

只要看到：

```text
PRIVATE KEY
```

就要特别注意。

不要：

- 发给别人
- 粘贴到网站
- 上传论坛
- 上传 GitHub
- 发送到聊天群
- 公开截图

---

## 四、User ID 是什么

创建 OpenPGP 密钥时，一般会填写名字和邮箱，例如：

```text
ggg <gggggg@disroot.org>
```

这就是一个 User ID。

它表示：

> 这把 OpenPGP 密钥声明自己对应这个名字和邮箱。

但这并不意味着：

> 这把密钥从密码学上只能给这个邮箱使用。

User ID 主要用于身份标记和帮助邮件软件自动匹配公钥。

---

## 五、一把 OpenPGP 密钥可以给多个邮箱使用吗

可以。

例如你有：

```text
ggg@disroot.org
ggg@gmail.com
ggg@outlook.com
```

完全可以只有一套：

```text
一个公钥
一个私钥
一个 Fingerprint
```

然后在同一把密钥中添加多个 User ID：

```text
同一把 OpenPGP 密钥

├─ ggg <ggg@disroot.org>
├─ ggg <ggg@gmail.com>
└─ ggg <ggg@outlook.com>
```

这样几个邮箱共用同一个私钥。

---

## 六、为什么最好把邮箱加入 User ID

从纯密码学角度来说，邮件到底发送到哪个地址并不决定能不能解密。

只要别人使用了你的同一把公钥加密：

```text
邮件
↓
使用你的公钥加密
↓
你使用对应私钥
↓
解密
```

就能完成加密通信。

但邮件客户端需要解决一个实际问题：

> 给 `abc@example.com` 发邮件时，应该选择哪一把公钥？

所以 Thunderbird、Kleopatra 等软件通常会根据 User ID 中的邮箱地址自动匹配。

因此更规范的方式是：

```text
一把密钥
+
多个自己的邮箱 User ID
```

---

## 七、多个邮箱是否应该共用一把密钥

### 适合共用的情况

如果这些邮箱都代表同一个公开身份，例如：

- 个人 Gmail
- 个人 Outlook
- 个人 Disroot
- 自己的域名邮箱

那么共用一把密钥会方便很多。

### 不适合共用的情况

如果这些邮箱属于不同身份，例如：

- 工作邮箱
- 私人邮箱
- 匿名邮箱
- 不同网名
- 不同项目身份

最好分别使用不同密钥。

因为同一个 Fingerprint 会把这些邮箱关联起来。

简单判断：

> **同一个身份，可以共用。**

> **希望身份隔离，最好分开。**

---

## 八、为什么要导入别人的公钥

如果你想给 Bob 发加密邮件，你需要 Bob 的公钥。

流程如下：

```text
你的邮件
↓
使用 Bob 的公钥加密
↓
发送给 Bob
↓
Bob 使用自己的私钥
↓
解密
```

因此：

> **想给谁发送 OpenPGP 加密内容，就需要谁的公钥。**

例如：

```text
Bob 公钥已导入
→ 可以给 Bob 加密

Tom 公钥没有
→ 无法正常给 Tom 做 OpenPGP 加密
```

---

## 九、导入别人公钥的第二个作用：验证签名

公钥不仅可以用于加密，还可以用于验证数字签名。

如果 Bob 给你发送了一封签名邮件，你可以使用 Bob 的公钥验证：

- 是否由 Bob 对应的私钥签名
- 内容有没有被修改

因此导入别人的公钥主要有两个用途：

```text
1. 给对方发送加密内容
2. 验证对方的数字签名
```

---

## 十、为什么还要验证公钥 Fingerprint

任何人都可以创建：

```text
Bob <bob@example.com>
```

这样的 OpenPGP 密钥。

仅凭名字和邮箱，不能证明这把公钥真的属于 Bob。

所以最好通过其他独立渠道核对 Fingerprint，例如：

- 当面
- 电话
- Signal
- 其他可信通信方式

确认：

```text
你看到的 Fingerprint
=
对方确认的 Fingerprint
```

确认一致之后，再认证这把公钥。

---

## 十一、加密和签名不是一回事

### Encrypt：加密

作用是：

```text
让没有私钥的人看不到内容
```

### Sign：数字签名

作用是：

```text
证明内容由对应私钥签名
+
证明内容没有被修改
```

但：

```text
签名 ≠ 加密
```

一封数字签名邮件仍然可能是明文。

比较理想的使用方式是：

```text
Encrypt
+
Sign
```

也就是：

> 内容保密，同时验证发送者身份和内容完整性。

---

## 十二、配置 OpenPGP 后，所有邮件都会自动加密吗

不会。

给自己的邮箱配置 OpenPGP：

```text
≠
以后所有邮件自动加密
```

如果要给 Bob 发送加密邮件，通常需要：

```text
你的 OpenPGP 密钥
+
Bob 的公钥
+
发送时启用加密
```

如果没有 Bob 的公钥，就无法正常给 Bob 做 OpenPGP 端到端加密。

---

## 十三、Thunderbird 配置 OpenPGP 后，网页邮箱会自动加密吗

不会。

例如：

```text
Gmail 账号
    │
    ├─ Thunderbird + OpenPGP
    │
    └─ Gmail 网页版
```

Thunderbird 中配置的 OpenPGP 不会自动改变 Gmail 网页版。

如果想在 Webmail 使用 OpenPGP，需要：

- 邮箱服务本身支持
- 使用浏览器 OpenPGP 扩展
- 或使用支持 OpenPGP 的独立邮件客户端

如果比较重视安全，通常更推荐在 Thunderbird 之类的独立客户端中管理私钥。

---

## 十四、RSA 和 ECC 应该怎么选

### RSA

常见选择：

```text
RSA 4096
```

优点：

- 兼容性好
- 老软件支持更好
- 技术成熟

缺点：

- 密钥比较大
- 计算相对较慢

对于邮件使用，一般不会明显影响体验。

### ECC

如果使用现代软件，例如：

- Thunderbird
- Kleopatra / GnuPG
- OpenKeychain

ECC 是很好的选择。

优点：

- 密钥更小
- 速度更快
- 安全性高
- 更适合现代设备

常见现代曲线包括：

- Ed25519
- Curve25519
- X25519

简单选择：

> **新建个人密钥、没有老软件兼容需求：优先考虑 ECC。**

> **非常看重老软件兼容性：可以选 RSA 4096。**

---

## 十五、公钥和私钥可以重复使用吗

可以。

OpenPGP 密钥本来就是设计成长期使用的。

例如别人给你发送 100 封加密邮件，都可以继续使用同一个公钥。

并不是每发送一封邮件就重新创建一套 OpenPGP 密钥。

所以：

```text
OpenPGP 公钥 → 可以长期重复使用
OpenPGP 私钥 → 可以长期重复使用
```

---

## 十六、换电脑怎么办

不需要重新生成密钥。

正确方式是：

```text
旧电脑
↓
导出 OpenPGP 私钥备份
↓
安全保存
↓
新电脑
↓
导入原来的私钥
↓
继续使用
```

重新导入后仍然是原来的：

- 公钥
- 私钥
- Fingerprint
- User ID

所以别人以前保存的你的公钥仍然可以继续使用。

---

## 十七、应该备份什么

最重要的是：

```text
私钥
```

例如：

```text
openpgp-private-key.asc
```

如果只备份公钥：

```text
-----BEGIN PGP PUBLIC KEY BLOCK-----
```

是不够的。

因为公钥不能帮你恢复解密能力。

---

## 十八、私钥备份密码是什么

导出私钥时，有些软件会要求设置备份密码。

作用是：

> 对导出的私钥文件再次进行加密保护。

例如：

```text
私钥
↓
备份密码保护
↓
private-key.asc
```

以后在其他设备导入时，可能需要输入这个密码。

---

## 十九、备份密码忘记了怎么办

### 当前设备里的私钥还在

通常问题不大。

可以：

```text
当前私钥
↓
重新导出
↓
设置新的备份密码
```

所以应该尽快重新备份。

### 只剩加密的私钥备份文件

如果：

```text
只剩 private-key.asc
+
忘记备份密码
```

那么通常无法恢复里面受保护的私钥。

因此真正需要长期保存的是：

```text
私钥备份文件
+
对应的备份密码
```

---

## 二十、为什么能看到私钥文件里的字符串

这是正常的。

例如：

```text
-----BEGIN PGP PRIVATE KEY BLOCK-----

lFgEZxxxxxxxxxxxxxxxxxxxxxxxx
xxxxxxxxxxxxxxxxxxxxxxxxxxxxx

-----END PGP PRIVATE KEY BLOCK-----
```

这些字符只是 OpenPGP 数据的文本表示形式。

即使肉眼可以看到，也不代表里面的私钥没有加密保护。

所以：

```text
能看到字符串
≠
能够绕过密码直接使用私钥
```

---

## 二十一、修改备份密码后，私钥字符串为什么会变化

这是正常的。

例如同一把私钥：

```text
原私钥
├─ 使用密码 AAA 导出 → 文件 A
└─ 使用密码 BBB 导出 → 文件 B
```

两个文件里的字符串可能完全不同。

但解密之后仍然对应同一把 OpenPGP 密钥。

因此通常不会改变：

- Fingerprint
- 公钥
- 密钥身份

变化的只是备份文件的保护方式。

---

## 二十二、能不能只保存 PRIVATE KEY BLOCK 字符串

技术上可以。

如果完整保存：

```text
-----BEGIN PGP PRIVATE KEY BLOCK-----
...
-----END PGP PRIVATE KEY BLOCK-----
```

以后可以重新保存成 `.asc` 文件再导入。

但不建议人工抄写，因为：

- 少一个字符可能失败
- 复制不完整可能失败
- 换行损坏可能失败
- 容易误操作

更好的方式是直接保存完整 `.asc` 私钥备份文件。

---

## 二十三、删除密钥后还能重新导入吗

可以。

只要你还有完整私钥备份：

```text
删除电脑里的密钥
↓
以后重新导入私钥
↓
恢复原来的密钥
```

它仍然拥有相同的：

- Fingerprint
- 公钥
- 私钥

以前的加密邮件也可以继续使用对应私钥解密。

### 删除和撤销不是一回事

```text
删除 Delete
```

只是从当前设备的密钥库移除。

```text
撤销 Revoke
```

则表示正式声明：

> 这把密钥不应该继续用于新的通信。

不要混淆这两个操作。

---

## 二十四、OpenPGP 密钥可以长期使用吗

可以。

如果密钥设置为永不过期，并且：

- 私钥没有泄露
- 算法仍然安全
- 没有主动撤销

那么可以使用很多年。

换电脑、重装系统、换客户端，都不代表必须重新生成密钥。

---

## 二十五、密钥到期怎么办

假设密钥设置：

```text
有效期：3 年
```

三年后通常不需要创建新密钥。

只要私钥还在，可以延长原密钥的有效期。

例如：

```text
原密钥
↓
到期
↓
修改有效期
↓
继续使用
```

Fingerprint 通常不会因为正常续期发生变化。

因此：

```text
密钥到期
≠
私钥消失

密钥到期
≠
历史邮件无法解密
```

---

## 二十六、永不过期还是设置有效期

两种方式都可以。

### 追求简单

可以设置：

```text
永不过期
```

但必须做好：

- 私钥备份
- 私钥保护
- 撤销准备
- 设备安全

### 追求规范

可以设置：

```text
3～5 年有效期
```

到期前再延长。

---

## 二十七、什么情况下应该真正更换密钥

以下情况比较适合生成新密钥：

- 私钥已经泄露
- 怀疑私钥泄露
- 设备失窃且私钥保护不足
- 原来的算法已经不推荐
- 希望重新隔离身份
- 主动进行密钥轮换

而以下情况通常不需要换密钥：

- 换电脑
- 重装系统
- 换邮件客户端
- 正常到期

---

## 二十八、换新密钥后，旧私钥不要随便删除

假设以前使用：

```text
Key A
```

后来换成：

```text
Key B
```

建议：

```text
Key A
→ 不再用于新的通信
→ 继续安全保存私钥

Key B
→ 用于新的通信
```

因为以前别人使用 Key A 公钥给你加密的内容，仍然可能需要 Key A 私钥才能解密。

---

## 二十九、keys.openpgp.org 是什么

`keys.openpgp.org` 是一个 OpenPGP 公钥服务器。

主要作用是：

> 帮助别人通过邮箱或 Fingerprint 找到你的公钥。

上传到密钥服务器的是：

```text
公钥
```

不是：

```text
私钥
```

私钥永远不应该上传到公钥服务器。

---

## 三十、为什么 keys.openpgp.org 会发邮箱验证邮件

假设你的密钥包含：

```text
ggg <ggg@disroot.org>
```

上传公钥之后，服务器需要确认：

> 这个邮箱是否真的由你控制。

所以会向该邮箱发送验证邮件。

验证成功以后，别人可以通过邮箱地址查找对应的公钥。

---

## 三十一、邮箱验证链接可以公开吗

不建议。

验证链接不是私钥，但它属于一次性或临时的验证凭证。

应该把它和下面这些链接一样对待：

- 邮箱验证链接
- 密码重置链接
- 登录确认链接

也就是：

> 不要公开分享。

如果不小心公开，最好重新申请一封新的验证邮件。

---

## 三十二、同一个邮箱以后还能生成新的 OpenPGP 密钥吗

可以。

例如现在：

```text
ggg@disroot.org
↓
Key A
```

以后可以重新生成：

```text
Key B
```

然后再次把：

```text
ggg@disroot.org
```

作为 User ID 并重新进行邮箱验证。

一个邮箱并不会因为以前用过某把 OpenPGP 密钥，就永远不能使用新的密钥。

---

## 三十三、为什么不要频繁更换密钥

因为每次生成新密钥：

```text
Fingerprint 都会变化
```

联系人原本保存的是：

```text
Key A
```

你换成：

```text
Key B
```

以后联系人需要更新你的公钥。

同时你自己还需要继续保留旧私钥，用于解密历史内容。

所以没必要：

- 换电脑就换密钥
- 换客户端就换密钥
- 每年固定换密钥

对于普通个人用户，更合理的是：

> **让一把密钥稳定使用较长时间。**

---

## 三十四、个人用户为什么适合一把密钥管理多个邮箱

如果有多个自己的邮箱：

```text
邮箱 A
邮箱 B
邮箱 C
邮箱 D
```

每个邮箱生成一把密钥：

```text
Key A
Key B
Key C
Key D
```

长期管理会比较麻烦。

如果这些邮箱属于同一个身份，可以使用：

```text
一套 OpenPGP 密钥
│
├─ 邮箱 A
├─ 邮箱 B
├─ 邮箱 C
└─ 邮箱 D
```

这样真正需要长期维护的主要是：

```text
一个私钥备份
+
一个备份密码
```

---

## 三十五、私钥需要记住吗

不需要。

没有必要背：

```text
-----BEGIN PGP PRIVATE KEY BLOCK-----
...
```

真正应该做的是：

```text
保存私钥文件
+
保存私钥备份密码
```

例如：

```text
openpgp-private-key.asc
```

密码则可以保存到可靠的密码管理器。

---

## 三十六、推荐的私钥备份方式

最好至少保留两份备份。

例如：

```text
电脑
│
├─ 当前使用中的私钥
├─ 加密 U 盘备份
└─ 第二份安全离线备份
```

可以考虑：

- 加密 U 盘
- 加密移动硬盘
- 密码管理器的安全附件
- 其他安全离线设备

不建议把未保护的私钥：

- 直接发送到自己的邮箱
- 上传公开网盘
- 上传 GitHub
- 发到聊天软件
- 粘贴到在线工具

## 三十七、OpenPGP 能隐藏所有邮件信息吗

不能。

OpenPGP 主要保护：

- 邮件正文
- 附件
- 数字签名内容

现代实现还可能保护邮件主题。

但邮件系统通常仍然需要暴露部分元数据，例如：

- 发件人邮箱
- 收件人邮箱
- 发送时间
- 邮件服务器
- 邮件大小
- 部分邮件 Header

所以 OpenPGP 是：

> **内容端到端加密**

而不是：

> **完全匿名通信系统**

---

## 三十八、TLS 和 OpenPGP 有什么区别

普通邮箱通常已经使用 TLS。

例如：

```text
你的设备
↓ TLS
邮件服务器
↓ TLS
对方服务器
```

TLS 主要保护邮件在传输过程中的连接。

服务器通常仍然可能读取邮件正文。

OpenPGP 则是：

```text
你的设备
↓
先加密
↓
服务器收到密文
↓
对方设备
↓
使用私钥解密
```

所以：

```text
TLS ≠ OpenPGP 端到端加密
```

## 三十九、推荐的个人 OpenPGP 使用方案

如果是普通个人用户，希望长期使用并尽量减少管理负担，可以考虑：

```text
现代 OpenPGP 客户端
+
ECC 密钥
+
一把长期使用的个人密钥
+
自己的多个邮箱 User ID
+
强密码保护私钥
+
至少两份私钥备份
+
验证重要联系人的 Fingerprint
```

例如：

```text
                 一套 OpenPGP 密钥
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
   Disroot 邮箱      Gmail 邮箱      Outlook 邮箱
          │              │              │
          └──────────────┼──────────────┘
                         ↓
                    同一个私钥
```

前提是这些邮箱本来就属于同一个身份，而且不介意它们被关联。

## 四十、最重要的几个原则

最后可以把 OpenPGP 压缩成几句话：

```text
公钥：
可以公开，可以发给别人。

私钥：
只由自己保存，不要泄露。

Fingerprint：
用于确认公钥身份。

User ID：
用于声明密钥对应的名字和邮箱。

别人给我加密：
使用我的公钥。

我给别人加密：
需要对方的公钥。

换电脑：
导入原来的私钥，不需要重新生成。

密钥到期：
通常续期即可。

私钥泄露：
撤销旧密钥并生成新密钥。

多个自己的邮箱：
可以共用一把密钥，但会产生身份关联。
```

## 四十一、适合个人用户的简单思路

如果你的几个邮箱本来就属于同一个身份，而且不介意它们被关联，那么没有必要把 OpenPGP 管理得过于复杂。

可以采用：

> **一个人，一套长期 OpenPGP 密钥，多个自己的邮箱 User ID，做好私钥备份。**

只有在工作、私人、匿名等身份需要相互隔离时，再考虑使用不同密钥。

真正值得重视的是三件事：

1. **私钥是否安全**
2. **私钥是否有可靠备份**
3. **重要联系人的公钥是否经过 Fingerprint 验证**

这三个问题处理好，个人 OpenPGP 的主要安全基础就建立起来了。
